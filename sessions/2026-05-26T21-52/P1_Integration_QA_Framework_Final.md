### 시나리오 1: 초기 연결 및 상태 표시 검증 (Connection & State Verification)
**목표:** 사용자가 앱에서 장치를 연결했을 때, UI상에 연결 상태가 즉각적이고 정확하게 반영되는지 확인한다.

| 단계 | 사용자 액션 (Mockup) | 시스템/하드웨어 반응 (Dev) | 기대 결과 (Visual Fidelity) | 검증 항목 | 통과 여부 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1.1 | 앱에서 BLE 스캔 시작 및 특정 장치 선택 | `BleSimulator.connect()` 호출, 하드웨어 연결 시뮬레이션 | UI에 '연결 중...' 상태 표시 (Progress Bar) | 연결 진행 중 애니메이션/텍스트가 Mockup과 일치하는가? | [ ] |
| 1.2 | 성공적인 연결 발생 | `connectionId` 발급 및 서비스 활성화 | UI에 '성공적으로 연결됨' 상태 및 장치 ID(`deviceId`) 표시 | 연결 성공 시의 색상(골드/Deep Teal) 및 타이포그래피가 디자인 가이드와 일치하는가? | [ ] |
| 1.3 | 연결 해제 요청 | `BleSimulator.disconnect()` 호출 | UI에 '연결 끊김' 상태로 전환 | 연결 해제 시의 애니메이션 및 오류 메시지가 명확한가? | [ ] |

### 시나리오 2: 실시간 데이터 스트리밍 검증 (Real-time Data Streaming Verification)
**목표:** 인슐린펌프에서 수신되는 혈당 데이터를 앱 UI에 지연 없이 정확하게 표시하는지 확인한다.

| 단계 | 사용자 액션 (Mockup) | 시스템/하드웨어 반응 (Dev) | 기대 결과 (Visual Fidelity) | 검증 항목 | 통과 여부 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 2.1 | 연결 상태 유지 및 데이터 수신 대기 | `receiveData()` 호출 시뮬레이션, BLE에서 데이터 발생 | UI의 혈당 값 영역이 실시간으로 업데이트되어야 함 | 데이터 수신 지연 시간(Latency)은 최대 Xms 이내인가? (기술 검증) | [ ] |
| 2.2 | 특정 혈당 값 수신 (예: 150 mg/dL) | Mocked Data Injection 시뮬레이션 | 혈당 값이 골드 강조 영역에 정확히 표시됨 | 데이터 표시 형식(소수점 자리, 단위)이 디자인 명세와 일치하는가? | [ ] |
| 2.3 | 경고 값 발생 (예: 250 mg/dL 초과) | 데이터 수신 시 Mockup의 알림 로직 트리거 | 화면에 즉각적으로 위험 알림(Warning State)이 표시됨 | 경고 상태 전환 시의 색상 변화(빨간색 계열 사용 여부)가 디자인 가이드와 일치하는가? | [ ] |

### 시나리오 3: 에러 및 예외 처리 검증 (Error & Exception Handling)
**목표:** 통신 오류, 권한 문제 등 비정상적인 상황 발생 시 사용자에게 명확하고 안전하게 피드백하는지 확인한다.

| 단계 | 사용자 액션 (Mockup) | 시스템/하드웨어 반응 (Dev) | 기대 결과 (Visual Fidelity) | 검증 항목 | 통과 여부 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 3.1 | 연결 불가 시도 | `connect()` 실패 시뮬레이션 | 명확한 오류 메시지 표시 | 오류 메시지가 사용자의 행동을 유도하는가? (모호하지 않은가?) | [ ] |
| 3.2 | 데이터 수신 실패 시뮬레이션 | `receiveData()`에서 타임아웃 또는 에러 발생 | 오류 알림(Toast/Snackbar)이 나타남 | 오류 피드백이 디자인 시스템의 표준 오류 컴포넌트를 따르는가? | [ ] |

## ✅ 최종 통합 검증 체크리스트 (Dev Team 배포용)

**[필수 항목]**
1. **실시간 동기화:** 연결/해제 상태 변화와 데이터 스트리밍 간의 UI 업데이트 지연 시간은 500ms 미만이어야 한다.
2. **컬러 일관성:** 성공(골드), 경고(주황/빨강), 오류(빨강) 색상 코드가 `colors.ts`에 정의된 값과 100% 일치해야 한다.
3. **데이터 포맷:** 수신되는 모든 혈당 데이터는 UI 표시 전에 백엔드에서 최종적으로 검증되어야 하며, 잘못된 포맷이 UI에 노출되어서는 안 된다.
