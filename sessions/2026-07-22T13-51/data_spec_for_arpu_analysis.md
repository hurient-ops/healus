# 데이터 요구사항 명세서: 상태-수익 관계 분석 (Step 1)# 목표: 기술적 안정성($P_0$) 변화가 사용자 평균 수익($ARPU$)에 미치는 인과관계를 정량화하기 위한 고품질의 시계열 데이터를 확보합니다.## 1. 수집 데이터 정의 (Data Schema Definition)개발팀은 모든 측정값이 다음 JSON 또는 CSV 포맷을 따르도록 데이터를 구조화해야 합니다. 최소한 다음 세 가지 핵심 지표를 각 사용자 세션/기간별로 기록해야 합니다.## 필드명| 설명| 단위| 계산 근거 및 중요성|:---|:---|:---|---|`session_id`|개별 BLE 통신 또는 상태 측정 세션 고유 ID|String|데이터 추적의 기본 키|`timestamp`|측정 시점 (UTC 기준)|ISO 8601|시간 기반 시계열 분석|`latency_crypto`|암호화(Crypto) 과정에 소요된 지연 시간|밀리초 ($\text{ms}$)|보안 처리의 성능 영향 측정|`latency_sync`|동기화(Sync) 과정에 소요된 지연 시간|밀리초 ($\text{ms}$)|상태 동기화의 성능 영향 측정|`stability_p0`|시스템 안정성 지표 ($P_0$)|실수 (0.0 ~ 1.0)|시스템의 기술적 안정성 정량화|`arpu_value`|해당 세션/기간 동안 발생한 사용자 수익 (또는 예상 ARPU)|원화 ($\text{KRW}$) 또는 달러 ($\text{USD}$)|결과 변수 (Dependent Variable)|## 2. 측정 방법론 및 기준 (Measurement Methodology)데이터의 신뢰도를 확보하기 위해 다음의 측정 기준을 엄격히 준수해야 합니다.1. **Latency 측정:**- 측정은 **BLE 통신 시작 시점부터 응답 수신 완료 시점까지**의 총 소요 시간으로 정의합니다. (이는 `simulate_ble_communication` 함수 로직과 일치해야 함)- 모든 Latency 값은 시스템 목표값($\text{Latency}_{\text{target}} = 50\text{ms}$)과의 **편차(Deviation)**를 함께 기록하여 측정의 민감도를 확보합니다.2. **안정성 ($P_0$) 정의:**- $P_0$는 시스템이 설정된 안정성 임계값($99.9\%$)을 달성했는지 여부를 이진(Binary) 또는 연속적인 확률값으로 정의해야 합니다. (예: $P_0 = 1$이면 목표 달성, $P_0 < 1$이면 실패)- **ETL 요구사항:** 개발팀은 데이터베이스에 저장 시, **실제 측정된 Latency와 $P_0$ 값**을 원시(Raw) 데이터로 반드시 보존해야 합니다.## 3. ETL 파이프라인 요구사항 (ETL Pipeline Requirements)수집된 원시 데이터를 최종 분석 포맷으로 변환하기 위한 파이프라인은 다음 단계를 포함해야 합니다.1. **데이터 정제 (Cleaning):- 결측치(Missing Values) 처리 규칙 정의: 결측치가 발생했을 경우, 해당 데이터 포인트는 **분석에서 제외하거나** 또는 **평균값으로 대체하는 방식**을 사전에 결정하고 적용해야 합니다. (이 결정은 Business 에이전트와 협의 필요)- 이상치(Outliers) 탐지 및 처리: 측정된 $\text{Latency}$ 값이 비정상적으로 높거나 낮을 경우, 이를 식별하고 개발팀에게 플래그를 올려 수동 검토를 요청해야 합니다.2. **특성 공학 (Feature Engineering):- 원시 Latency 값($\text{latency}_{\text{crypto}}, \text{latency}_{\text{sync}}$)을 **평균, 중앙값, 표준편차**로 집계하여 통계 모델 입력 변수로 사용해야 합니다.- $P_0$의 변화(이산적인 상태 변화)가 $ARPU$에 미치는 영향을 분석하기 위해, 연속적인 $\text{Latency}$ 값과 이산적인 $P_0$ 값을 결합한 **상호작용 항($\text{Latency} \times P_0$)**을 생성하는 파이프라인을 구축해야 합니다.3. **데이터 저장 (Storage):- 최종 분석 데이터는 시계열 분석에 최적화된 형태(예: Time-Series Database 또는 Pandas DataFrame)로 저장되어야 하며, **실시간 대시보드 연동 가능성**을 염두에 두고 설계되어야 합니다.
