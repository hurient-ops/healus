# 🖼️ 통합 검증 프레임워크: Mockup-Dev 실시간 일치 검증 시스템

## 🎯 목표
개발 결과물(Code)과 최종 디자인 의도(Mockup) 간의 시각적 및 기능적 일치성을 **자동화된 프로세스**를 통해 실시간으로 검증한다.

## ⚙️ 기반 시스템 (Baseline System)
모든 검증은 다음의 확정된 디자인 가이드라인을 기준으로 수행되어야 한다.
*   **컬러 팔레트:** 골드 (`#FFD700`), Deep Teal (`#004D40`)
*   **레이아웃 좌표 기준:** 핵심 정보 배치에 대한 명확한 픽셀/퍼센트 정의.

## 1단계: 입력 및 기준 정의 (Input & Baseline Definition)

### A. 핵심 디자인 시스템 참조 (Design System Reference)
| 요소 | 값 | 용도 |
| :--- | :--- | :--- |
| **Primary Color** | `#FFD700` (골드) | 중요 알림, CTA 강조 |
| **Secondary Color** | `#004D40` (Deep Teal) | 배경, 안정 상태 표시 |

### B. QA 체크리스트 통합 항목 (Integrated Checklist Items)
기존 기능 검증에 시각적 일치성 검증 단계를 추가한다.

| ID | 영역 | 기능적 QA (DevCheck) | **시각적 QA (DesignCheck)** | 측정 기준 |
| :---: | :--- | :--- | :--- | :--- |
| P1-F01 | 데이터 표시 | BLE 수신 및 혈당 값의 정확한 전송/표시 여부. | **색상 일치:** 핵심 수치(혈당)에 적용된 색상이 디자인 가이드라인을 따르는가? | 1:1 매칭 (Color Code Check) |
| P1-F02 | 상태 표시기 | 알림 발생 시 UI 컴포넌트가 정확히 활성화되는가? | **레이아웃 일치:** 알림 메시지의 위치와 크기가 Mockup의 레이아웃 좌표와 일치하는가? | 픽셀/좌표 비교 (Layout Match) |

| P1-F04 | 컴포넌트 구조 | 전체 화면 레이아웃과 컴포넌트 계층 구조의 구현. | **구조 일치:** 사용된 UI 컴포넌트가 최종 디자인 파일의 컴포넌트 명세와 동일한지 확인. | 컴포넌트 매핑 (Component Mapping) |

## 2단계: 실시간 검증 프로세스 (Real-time Verification Process)

### [Step 1: 개발 결과물 생성]
코다리(Developer)가 기능 구현 및 UI 컴포넌트를 완성하여 빌드한다.

### [Step 2: QA 체크리스트 실행]
개발팀은 `DevTeam_P1_QA_Checklist.md`에 명시된 **기능적 QA 항목 (P1-F01 ~ P1-F04)**을 수행하고 결과(Pass/Fail)를 기록한다.

### [Step 3: 시각적 일치성 검증 (Designer's Role)]
개발팀은 다음의 **시각적 검증 도구**를 사용하여 구현된 화면과 기준 디자인 파일 간의 차이를 확인한다.

1.  **Color Check:** 구현된 요소의 실제 Hex 코드를 추출하여, `Design System Reference`의 색상 코드와 비교한다.
2.  **Layout Check:** 화면 내 핵심 요소들의 상대적 위치(좌표)를 측정하여, Mockup 파일에 정의된 좌표와 오차 범위를 확인한다. (오차 범위: ±5px)
3.  **Typography Check:** 텍스트 레이블과 값의 CSS/Style 속성을 추출하여, 디자인 가이드라인의 폰트 크기 및 굵기가 준수되었는지 자동 검사한다.

### [Step 4: 통합 보고서 생성]
모든 QA 결과는 하나의 통합 보고서로 집계된다.
*   **보고서 형식:** `Integrated_QA_Report_[BuildID].md` 파일 형태로, 기능적 Pass/Fail과 시각적 일치성 점수(Visual Match Score)를 함께 제시한다.

## 3단계: 최종 산출물 (Final Deliverable Blueprint)
이 프레임워크는 개발팀에게 다음의 **실행 가능한 지침**을 제공한다.

*   **목표:** 기능적 안정성(P1-F01~F04)이 시각적 일치성 점수와 직접적으로 연결되도록 강제한다.
*   **결과 지향:** 추상적인 '일치'가 아닌, **측정 가능한 수치(코드/픽셀)**로 디자인 의도 준수 여부를 판단하게 한다.
