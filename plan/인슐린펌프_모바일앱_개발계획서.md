**인슐린펌프 모바일 앱 개발 계획서**

본 문서의 목적은 인슐린 펌프 디바이스와 완벽히 동기화되어 상태 모니터링,
제어, 로그 수집을 안전하게 수행하는 모바일 애플리케이션을 개발하는
것이다.

## **개발환경 및 구조**

1.  플랫폼 : Cross-platform

2.  프레임워크 : Flutter 또는 React Native

3.  BLE Library : flutter_blue_plus

4.  의료기기에 적합한 데이터베이스 선택

5.  테스트의 용이성, 유지보수성, 확장성을 고려한 아키텍처 선택

6.  모바일 OS가 백그라운드로 진입하여 정보를 수신하지 못하는 경우를
    대비하여 Foreground service로 동작하거나 백그라운드 복원 (State
    Preservation and Restoration) 서비스 적용

## **개발 시 반드시 지켜야 할 원칙**

1.  현재 동작하는 UI화면(./ui_design 폴더)과 멀티모달, 버튼 클릭시
    이동화면, 네비게이션 이동화면은 100% 그대로 유지해야 함 (즉, 모든
    UI와 화면 기능은 절대 수정하면 안되고, BLE통신을 통해 송수신하는
    메시지 통신과 데이터 매핑을 중심으로 개발해야 함)

2.  화면 이동, 테스트를 위해 임시로 설정한 값들과 조건, 타이머 등은 모두
    code.html 파일에 정의되어 있으며, 이 내용을 100% 준수해야 함 (자세한
    사항은 아래 내용에 포함되어 있음)

3.  BLE 연결 실패시 대응방안(타임아웃 및 재시도) : 최대 누적 대기시간
    3초 초과시 타임아웃 처리 후 재시도한다.

4.  패킷 재조립 타임아웃 설정: 10byte 분할 수신 시 첫번째 청크 수신 후
    두번째 청크가 오지 않을 경우를 대비하여 500ms로 타임아웃을 설정하고
    타임아웃 발생시 버퍼 초기화 및 재연결을 시도해야 한다.

5.  재시도 후에도 BLE 연결이 되지 않거나 정보를 받을 수 없는 경우 모든
    화면과 기능이 테스트 모드로 진입하여 수행하며, 추후 테스트 모드
    부분은 삭제할 것을 염두에 두고 개발 해야함 (관련 내용을 아래에
    테스트 모드로 표시하였음)

6.  모든 메시지 규격과 통신 절차 및 프로토콜은 Message Definition
    Specification(./plan/In_pump_msg_set_260606.md)을 철저하게 지켜서
    개발해야 함

## **공통사항**

1.  인슐린펌프로부터 수신된 정보와 현재 진행 중인 상태에 대한 정보는
    모두 데이터베이스에 저장하여 관리하고 공통으로 이용한다.

2.  화면에 표시하는 값들은 모두 공통 장소에 저장된 값을 기준으로 한다.

3.  현재 개발된 코드에 공통 장소가 정의되어 있으면 최대한 활용한다.

4.  모든 화면(멀티모달 화면 제외)에서 닫기 버튼을 누르면 실행했던 내용을
    취소하고 원상 복귀한 후 이전 화면으로 돌아간다. (이전 화면으로
    돌아가는 동작은 이미 개발되어 있으므로 개발코드 100% 반영)

5.  개발된 화면과 버튼을 눌렀을 때의 이동동작, 멀티모달 팝업,
    아이콘(배치) 생성 및 소멸 등 UI관련 화면은 100% 그대로 적용한다.

## **장치 연결 (해당 UI : ./ui_design/ble_connect 폴더의 화면)**

1.  BLE 스캔 및 연결: 디바이스 이름 또는 UUID로 탐색하고 탐색된 장비를
    표시한다. 표시 방법은 장비명과 BLE 고유 식별 MAC주소(12자리, 6byte)
    형태로 표시한다. (테스트 모드: 이미 프로그램에 정의된 장비가 검색된
    것으로 표시)

2.  세션 시작:

- 인슐린펌프 -\>\> 앱 : BT_START_REQ (0x01) 메시지 전송

- 앱 -\>\> 인슐린펌프 : BT_CONNECTABLE_CTRL_REQ(0x02) 메시지 전송

3.  상태 조회: BT_STATE_REQ(0x04)를 통해 인슐린펌프 상태 정보를
    요청하고, BT_STATE_IND(0x05)를 수신하여 상태정보를 획득한다. (테스트
    모드: idle로 인정하고 통과)

4.  현재 인슐린펌프 상태가 Idle이고, 오류가 없는 경우에만 통신을 계속
    진행한다. Idle상태확인이 안될 경우, BT_STATE_REQ(0x04)를 재전송, 2차
    Idle상태 확인시에도 상태가 Idle상태가 아니면 시스템 리셋 메시지
    BT_SYSEM_RESET(0x43)를 전송한다. (테스트 모드: idle상태가 확인된
    것으로 인정하고 통과)

5.  시간 동기화: BT_CUR_TIME_IND(0x06)를 통해 스마트폰의 현재 시간을
    인슐린펌프에 전송한다.

6.  시간 동기화 확인: BT_CUR_TIME_IND(0x06)를 통해 앱에서 보내준 시간을
    인슐린펌프가 다시 BT_CUR_TIME_RES(0x44)를 통해 앱에게 전송한 결과를
    비교하여 맞지 않으면 BT_CUR_TIME_IND(0x06)을 재전송한다. 재전송 후
    BT_CUR_TIME_RES(0x44)를 통해 수신한 정보가 또 맞지 않으면 시스템
    리셋 메시지 BT_SYSEM_RESET(0x43)를 전송한다. (테스트 모드: 시간을
    확인한 것으로 인정하고 통과)

## **암호 입력(해당 UI :./ui_design/password 폴더의 페이지)**

1.  비밀번호 인증: BT_PRS_APP_PASSWD_REQ(0x41)를 통해 비밀번호를
    요청하고, BT_PRS_APP_PASSWD_RES(0x42)를 수신하여 비밀번호를 공통
    장소에 저장한다. 입력된 비밀번호가 저장된 비밀번호와 맞으면
    통과한다. (테스트 모드: 이미 프로그램에 정의된 “000000”으로 확인 및
    인증통과)

2.  개발된 UI code는 100% 그대로 적용한다.

3.  인슐린펌프에서 비밀번호를 변경하면 전송되는
    BT_NEW_APP_PASSWD_IND(0x42) 메시지의 값으로 공통 장소에 저장된
    비밀번호를 업데이트한다.

## **대시보드: 이력 및 설정정보 조회(해당 UI : ./ui_design/dashboard 폴더의 페이지)**

1.  BT_BATT_DATA_REQ(0x70)를 통해 인슐린펌프 배터리 잔량을 요청하고,
    BT_BATT_DATA_RES(0x72)를 통해 수신한 정보를 배터리 잔량으로 공통
    장소에 저장하고 저장된 값을 대시보드의 프로그레시브 바에 연동하여
    표시한다. (테스트 모드: 이미 프로그램에 정의된 값으로 표시) 배터리
    잔량 요청은 30분(시간은 수정할 수 있도록 적용)에 한번씩 주기적으로
    진행하도록 개발한다. 인슐린펌프에서 BT_BATT_DATA_IND(0x71)을 통해
    배터리 잔량을 보내면 수신된 값으로 공통 장소에 저장된 배터리 잔량을
    업데이트 한다.

2.  BT_PUMP_PID_REQ(0x09)를 통해 인슐린펌프 고유의 PID를 요청하고,
    BT_PUMP_PID_RES(0x0A)를 통해 수신한 정보를 인슐린펌프 고유 PID로
    공통 장소에 저장한다.

3.  이력 조회: BT_LOG_INJ_QNT_REQ(0x1E)를 통해 금일 주입량 정보를
    요청하고 BT_LOG_INJ_QNT_IND(1F)를 통해 수신한 시, 분, 초, 기초
    누적량, 아침 누적량, 점심 누적량, 저녁 누적량, 추가 누적량으로 공통
    장소에 저장한다. 대시보드의 오늘의 요약에 저장된 값을 연동하여
    표시한다. 기초 누적량은 기초주입, 아침, 점심, 저녁 누적량은 합산하여
    식사주입, 추가 누적량은 추가주입으로 매핑한다. (테스트 모드: 이미
    프로그램에 정의된 값으로 표시)

4.  주입정보 조회: BT_INJ_INFO_REQ(0x15)를 통해 식사주입(0x00)을
    선택하여 주입정보를 요청하고, BT_INJ_INFO_RES(0x16) 통해 수신된
    주입정보((주입정보 종류, 날짜, 설정 값, 인슐린 잔량)를 공통 장소에
    저장한다. 이 중 인슐린 잔량은 화면의 인슐린 잔량과 연동하여
    표시한다.

5.  긴급 정지 버튼을 클릭하면 현재 진행 중인 모든 프로세스가 종료되고,
    BT_INJ_STOP_REQ(0x37)을 전송한다. 현재 진행 중인 모든 동작(주입 중
    상태 등)을 멈춘다.

## **식사 주입 (./ui_design/meal_injection 폴더의 페이지)**

1.  식사 주입 설정 값 요청: BT_EAT_VALUE_REQ(2D)를 통해
    식사(아침,점심,저녁) 설정 값을 요청하고, BT_EAT_VALUE_RES(2E)를 통해
    수신한 정보를 식사 설정 값(아침설정 값, 점심설정 값, 저녁설정
    값)으로 공통 장소에 저장한다. 저장된 각각의 값은 식사 주입 페이지의
    아침, 점심, 저녁 설정 값으로 표현한다. (테스트 모드: 이미 프로그램에
    정의된 값으로 표시)

2.  식사 주입 정보 요청: 주입하기를 선택할 경우 BT_INJ_INFO_REQ(0x15)를
    통해 식사주입(0x00)을 선택하여 주입정보를 요청하고,
    BT_INJ_INFO_RES(0x16) 통해 수신된 주입정보(주입정보 종류, 날짜,
    인슐린 설정 값, 인슐린 잔량)로 공통 장소의 주입정보를 업데이트 한다.

3.  주입하기 버튼을 누르면 식사주입 코드(0x00)와 인슐린 설정 값을
    BT_INJ_REQ(0x17)에 적용하여 인슐린펌프로 전송한다.

4.  BT_INJ_START_IND(0x3A) 메시지를 수신하면 주입이 시작되었다는 상황을
    인지하고 주입 중 상태로 전환한다. 현재 개발된 화면이동과
    아이콘(배지), 멀티모달 팝업을 100% 적용한다.

5.  BT_INJ_STOP_IND(0x3B) 메시지는 주입이 종료되었다는 알림이며, 주입 중
    상태를 종료한다. 현재 개발된 화면이동과 아이콘(배지), 멀티모달
    팝업을 100% 따른다. (테스트 모드: 이미 프로그램에 정의된 테스트용
    카운터를 이용한 주입 종료 적용)

6.  주입 중 상태와 주입 종료 메시지 수신은 전체 앱이 공유할 수 있어야
    하며, 주입 중에는 식사 주입으로 진입할 수 없으며, 주입 종료 메시지가
    오면 어느 화면에 있더라도 대시보드 화면으로 이동하여 주입 중 상태를
    종료한다. 또한 긴급정지 버튼을 누르면 주입 중 상태를 즉시 종료한다.
    또한 긴급정지 버튼을 누르면 주입 중 상태를 즉시 종료한다. 여기에
    필요한 UI와 code는 개발되어 있으며, 화면이동, 아이콘(배지), 멀티모달
    팝업 화면 등 모든 UI적 요소는 기존 프로그램에 정의된 내용을 100%
    적용한다. (테스트 모드: 이미 프로그램에 정의된 테스트용 카운터(5초)
    적용)

## **회식 적용 (./ui_design/dining 폴더의 페이지)**

1.  식사 주입 설정 값 요청: 식사 주입과 동일한 프로세스로 진행하며,
    아침설정 값, 점심설정 값, 저녁설정 값은 공통 장소에 저장 및 업데이트
    한다. (테스트 모드: 이미 프로그램에 정의된 값으로 표시)

2.  회식 적용 화면의 시간 설정(1시간~8시간)에서 원하는 시간을 선택하면
    시간설정 값을 공통 장소에 저장하고, 저장된 값을 시간 설정에 매핑하여
    표시한다. 회식적용 버튼을 누르면 회식모드 설정 코드(0x01)와 저장된
    회식시간 값을 BT_RECEPTION_SET_REQ(0x14)에 적용하여 인슐린펌프로
    전송한다.
